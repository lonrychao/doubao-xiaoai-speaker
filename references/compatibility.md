## 找不到设备的处理（did 翻车三连）

`did` 填米家APP里的设备名称，最常见三种翻车：

1. **多空格**：`小爱音箱 Pro` 与 `小爱音箱Pro`
2. **大小写/错别字**：`小爱音响`
3. **Mina 与 MIoT 两套名称不一致**

处理办法：`.migpt.js` 中设 `enableTrace: true`，重启后从日志中找 `miotDID` 的数字 ID，直接填进 `did`（数字 ID 最稳，不受名称差异影响）。

## 连续对话的机型差异

- 部分机型无法正确查询"播放状态"，会导致回答被中途打断。此时需关闭连续对话（`streamResponse: false`），或补充 `playingCommand: [3, 1, 1]`。
- Pro（LX06）顶部指示灯常亮表示正在聆听，是连续对话体验最好的机型。

## 多设备 / 吸顶音箱场景

- MiGPT 的核心绑定对象是「能听说话、能响应"小爱同学"的那台语音主机」。
- 吸顶音箱、副音箱若只是被动喇叭（跟着主机发声、自己不联网），**无需单独配置**。
- 若它们是在米家APP里有独立设备名的智能音箱，需作为多设备分别配置。
